# lhg-sa-essay：多轮改写技法

> 目标：把"写一遍"变成"改三遍"。好文书是改出来的，不是写出来的。
> 核心纪律：**一轮只改一类问题；改写不许引入素材清单之外的经历与数字。**

## 1. 何时使用

- 大纲已确认，要出初稿 → 第 3 节第一轮
- 初稿写完，觉得"平淡" → 第 4 节语言轮
- 终稿前抛光 → 第 5 节细节轮 + 审计脚本

## 2. 输入输出

**输入**：已确认的大纲（第一轮）或上一轮稿件。

**输出**：每轮输出一版稿件 + 本轮修改清单（改了哪几处、为什么）。

修改清单模板：
```markdown
## 第 N 轮修改清单
- [结构/语言/细节] 第 X 段：<改了什么> → <为什么>
```

## 3. 第一轮：结构轮（搭骨架）

目标：结构完整、信息齐全。文笔先不管，句子丑没关系。

步骤：
1. 按大纲逐段写，每段先写出"回答问题的那句话"（段落主旨句），再补支撑细节
2. 写完对照大纲检查：每段是否回答了预设问题？经历卡片是否都用上了？
3. 只调段落顺序与详略：哪段太长砍，哪段太单薄补（补的内容只能来自素材清单）
4. 本轮结束标准：大纲里的每个问题都有段落回答

## 4. 第二轮：语言轮（换血）

目标：删掉所有正确的废话，换成具体细节。

### 4.1 陈词替换表

| 陈词 | 问题 | 换法 |
|---|---|---|
| 从小就热爱 | 每个申请人都这么写 | 换成具体的第一次接触场景 |
| 怀揣梦想/追逐梦想 | 空 | 删掉，直接讲你做了什么 |
| 受益匪浅/刻骨铭心 | 感受词，无信息 | 换成"具体学到了什么+后来怎么用的" |
| 孜孜不倦/废寝忘食 | 自夸，无证据 | 换成具体行为（"连续三周每天… "） |
| 不是终点而是起点 | 烂大街的收尾 | 换成具体的下一步计划 |
| 扬帆起航/追逐梦想 | 比喻空转 | 删掉比喻，写事实 |

### 4.2 空话删除术

三步检验每个形容词：
1. 这个形容词删掉，句子信息量变少吗？（"重要的经历"→删掉"重要的"试试）
2. 能换成数字吗？（"很大的进步"→"从 X 提升到 Y"）
3. 能换成场景吗？（"刻苦学习"→"连续三周每天在实验室待到闭馆"）

### 4.3 数字锚定法

每段至少锚定 1 个数字：年份、人数、时长、金额、排名、比例。
没有数字的段落，读起来像散文——回去翻素材清单找数字，找不到就标"待补充"，不许编。

### 4.4 句式

- 短句优先：一句话只讲一件事，超过 40 字的句子拆
- 主动语态："我重写了清洗流程" > "清洗流程被我重写了"
- 删"非常/十分/特别"：这些词出现 3 次以上，说明形容词穷了

### 4.5 开头结尾专项

**开头三稿法**：第一轮先写三个不同钩子（场景/问题/反差），让用户选一个再展开。不要在第一轮就定死开头——开头是全文改得最多的地方。

**结尾禁区**：
- 不许喊口号（"我将为人类进步贡献力量"）
- 不许新开话题（结尾段出现全新经历 = 结构事故）
- 不许重复开头（"正如开头所说"是最偷懒的收束）

**结尾正例结构**："短期计划（一句话）+ 与项目的连接（一句话）+ 回扣开头意象（一句话）"，三句收束。

### 4.6 推荐信改写注意

- 推荐信是第三人称，注意人称统一（全文"他/她"，不许出现"我觉得他…"和"该生…"混用）
- 推荐人的口吻：老师不会用饭圈词汇，"宝藏男孩"式表达一律删
- 数字 double-check：推荐信里的数字（排名/比例）必须与申请人确认，不许沿用 PS 里的数字想当然

## 5. 第三轮：细节轮（抛光）

目标：零低级错误，字数合规。

### 5.1 细节清单

- [ ] 数字核对：文中的每个数字与 `materials.md` 一致（GPA、排名、年份）
- [ ] 人称时态：PS 全文第一人称，时态统一（经历用过去时，规划用将来时）
- [ ] 专有名词：学校名、教授名、课程名拼写准确（错一个名字，前功尽弃）
- [ ] 字数：跑 `essay_audit.py`，LEN 规则先手自查
- [ ] 标点：中英标点统一（中文文书不用半角逗号）
- [ ] 占位符：全文搜索 `[`、`XXX`、`待定`，一个不留

### 5.2 朗读测试

全文读出声一遍（或默读时逐字过）：
- 拗口的句子 → 重写
- 一口气读不完的句子 → 拆
- 读到某处想笑/想皱眉 → 那个地方就是有问题

### 5.4 终稿前夜清单（提交前 24 小时）

- [ ] 把 PS 打印出来（或换设备）读一遍——换载体能发现屏幕上看不见的问题
- [ ] 专有名词最后核对一遍：学校名、教授名、课程名（错一个名字，前功尽弃）
- [ ] 字数：复制到申请系统文本框里看实际计数（不同系统计数口径可能差 1~2%）
- [ ] 让一个不了解你申请的人读开头 30 秒，问他记住了什么
- [ ] 睡一觉再提交——80% 的低级错误是在"再读一遍"时发现的

### 5.5 改写前后的对照习惯

每轮改写保留 diff 习惯：把"改前句 → 改后句 → 改的理由"记下来。三个好处：

1. 用户能看懂你改了什么，而不是收到一篇"面目全非"的稿子
2. 下次写别的文书时，对照表就是你的个人语料库
3. 避免反复横跳：同一句话改回去又改回来，说明第一轮就没想清楚

## 6. 反模式

- ❌ 三轮并作一轮改——结构问题会伪装成语言问题，越改越乱
- ❌ 改写时"优化"出素材清单里没有的数字——这是编造，不是改写
- ❌ 用户说"帮我把 GPA 写高一点"——拒绝，这是诚信红线，不是文笔问题
- ❌ 只改错别字就叫"改完了"——错别字是第 5 节的事，前两轮没走等于没改
- ❌ 反复改 10 轮——三轮是上限，再改就是焦虑，不是进步；第 4 轮起必须说明改的理由

## 7. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 本轮是否只改了一类问题？→ 混改了就拆出来重做。
2. 修改清单是否写了"为什么"？→ 只写"改了什么"不算数。
3. 是否引入了素材清单之外的经历/数字？→ 有一条，本轮作废。

标准冒烟用例：用 `fixtures/bad/ps-bad.md` 走一遍三轮改写流程，确认输出稿的 blocker 清零（见 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-study-abroad/issues，正文写清"输入 → 错误输出 → 期望输出"。
