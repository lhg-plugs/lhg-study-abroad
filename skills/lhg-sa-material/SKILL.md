# lhg-sa-material：背景素材梳理

> 目标：把申请人脑子里零散的经历，变成一张"可直接用来搭结构"的素材清单。
> 核心纪律：**只记录用户亲口说的；记不清就标"待补充"，绝不脑补、绝不编造。**

## 1. 何时使用

- 用户说"我要写 PS / 推荐信" → 先走本 skill，不许直接写稿
- 用户发来一份简历 → 用第 3 节方法把简历翻译成"经历卡片"
- 改写阶段发现素材不够 → 回到本 skill 补采，而不是编

## 2. 输入输出

**输入**：用户口述的背景、简历、成绩单（成绩单只用来核对数字，不直接引用敏感信息）。

**输出**：`materials.md`，包含：
1. 五维素材表（教育 / 科研 / 实习 / 活动 / 获奖）
2. 经历卡片（每段重要经历一张卡：时间、角色、行动、数字、可提炼品质）
3. 待补充清单（用户记不清、需要回去确认的项）
4. 含金量排序（哪几张卡是主菜，哪几张是配菜）

## 3. 分步方法论

### 3.1 五维采集清单

| 维度 | 采集要点 | 易漏的追问 |
|---|---|---|
| 教育背景 | 学校、专业、GPA、排名、核心课程成绩 | 有没有哪门课的成绩特别能说明问题？ |
| 科研经历 | 实验室、课题、你的具体分工、产出（论文/专利/系统） | 你的工作和别人的工作边界在哪？ |
| 实习实践 | 公司、岗位、负责的模块、业务结果（数字） | 这个结果里，你的贡献占比大概多少？ |
| 课外活动 | 社团、竞赛、志愿者、担任的职务 | 有没有"从 0 到 1"做起来的事？ |
| 获奖荣誉 | 奖项名称、级别、获奖比例 | 这个奖项的含金量（参评人数/获奖比例）？ |

### 3.2 STAR 追问法

每段经历追问四要素，缺一不可：

- **S（情境）**：当时是什么背景？（"实验室要赶一个项目 deadline"）
- **T（任务）**：你的任务是什么？（"我负责数据清洗模块"）
- **A（行动）**：你具体做了什么？（"重写了清洗流程，把耗时从 6 小时压到 40 分钟"）
- **R（结果）**：结果如何？能量化吗？（"流程被实验室沿用至今"）

追问技巧：
- 用户说"我参与了 XX 项目" → 追问"你的具体分工是什么？和别人的边界在哪？"
- 用户说"取得了不错的成绩" → 追问"具体数字是什么？排名？比例？"
- 用户说"大概""可能""应该" → 标记"待补充"，不许按确定事实记录

### 3.3 经历卡片模板

```markdown
## 经历卡片：<一句话标题>
- 时间：2024.09 – 2025.06
- 角色：<你的具体角色，不是"成员"这种模糊词>
- 情境：一句话背景
- 行动：2~3 条，每条带数字
- 结果：量化结果 + 影响范围
- 可提炼品质：<如：调试耐心、工程素养、质疑精神>（只写证据支撑的）
- 状态：已确认 / 待补充（缺什么写清楚）
```

### 3.4 含金量排序

排序标准（按优先级）：
1. **有数字**：能量化的经历 > 纯描述的经历
2. **有转折**：遇到困难→解决 的经历 > 一帆风顺的经历
3. **有独特性**：别人没有的经历 > 人人都有的经历（如"学生会部长"除非有具体政绩）
4. **有相关性**：与目标专业相关的经历优先

排序后标出"主菜"（2~3 张，PS 的核心段落用）和"配菜"（其余，一句话带过或不用）。

### 3.5 待补充清单

```markdown
## 待补充
- [ ] 创新项目的具体起止时间（用户记不清，需查邮件）
- [ ] 竞赛获奖比例（需查官网）
- [ ] 实习转正答辩的评分（需问主管）
```

待补充项不许进经历卡片的"已确认"区，更不许进大纲。

### 3.6 跨维度素材复用

同一段经历可以在不同文书里承担不同功能，但**同一篇 PS 里不许重复讲同一件事**：

| 经历 | 在 PS 里的功能 | 在推荐信里的功能 |
|---|---|---|
| 科研项目 | 讲"反思与成长" | 老师讲"具体事例+比较级" |
| 实习 | 讲"动机/职业认知" | 上级讲"业务结果数字" |
| 竞赛 | 讲"转折/韧性" | 慎用（老师多半没亲历） |

### 3.7 简历 → 素材翻译对照

用户直接甩简历过来时，按此表翻译：

| 简历写法 | 翻译成素材时要追问的 |
|---|---|
| "参与 XX 项目" | 具体分工？你的代码/文档在哪？ |
| "获得 XX 奖" | 获奖比例？参评人数？ |
| "熟悉 Python" | 写过多少行？做过什么项目？ |
| "担任部长" | 任期内做了哪 2~3 件具体事？ |
| "GPA 3.8" | 排名？核心课程分数？ |

### 3.8 追问话术库（直接可用）

- 开场："我们先从你印象最深的一段经历开始，不用按时间顺序。"
- 挖数字："这个'不错'大概是什么量级？比如人数、金额、比例？"
- 挖边界："这个项目里，哪些是你做的，哪些是别人做的？"
- 挖转折："过程中有没有哪个时刻你觉得'完了'？后来怎么解决的？"
- 收尾："还有没有哪段经历，你觉得'不值一提'但其实挺特别的？"（好素材常藏在这里）

## 4. 反模式

### 4.1 真实翻车案例（抽象后的教训）

- 案例 A：申请人说"发表过论文"，追问后发现是挂名第七作者——卡片上如实写"第七作者（挂名）"，PS 里不许暗示一作。
- 案例 B：实习公司不让透露业务数据——用"某头部电商"替代公司名可以，但业务数字必须模糊化并经主管确认，不许编具体数字。
- 案例 C：竞赛获奖证书丢了——标记"待补充（需补开证明）"，PS 初稿里先不写这段，避免终稿时证明开不出来。

## 5. 自检与反馈

- ❌ 用户说"记不清了"，你替他编个数字——这是学术不端的起点
- ❌ 把"参与"写成"主导"，把"协助"写成"负责"——动词升级等于造假
- ❌ 简历上有什么就全用——PS 不是简历扩写，素材要精选（见 3.4）
- ❌ 跳过素材采集直接写稿——没有素材的稿子只能靠编，这是本插件要消灭的流程
- ❌ 问用户要成绩单照片、身份证等敏感材料——核对数字口头确认即可，不经手敏感文件

## 5. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 素材清单里的每条数字，用户亲口确认过吗？→ 没确认的是否标了"待补充"？
2. 有没有出现用户没说过的经历/成绩？→ 有一条，本次执行就不合格。
3. 经历卡片是否按 3.4 排过序？"主菜"是否得到了用户认可？

标准冒烟用例：用本仓库 `fixtures/good/meta.json` 的目标信息，检查素材→结构→成稿链路中数字是否一致（见 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-study-abroad/issues，正文写清"输入 → 错误输出 → 期望输出"。
